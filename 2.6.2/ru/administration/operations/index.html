    Операции¶

    Инструменты для ежедневного управления панелью: переключатель обслуживания для запланированных работ, показатели и проверка работоспособности для вашего мониторинга, оповещения, напоминания об истечении срока действия для подписчиков и удаленные копии резервных копий.

    Режим технического обслуживания¶

    Настройки → Общие → Техническое обслуживание закрывает панель для ее клиентов на время работы с ней (миграция, восстановление, крупное обновление):

    • Client apps get a maintenance answer: player_api answers user_info.status Maintenance with the message, which apps show; playlists, XMLTV, Enigma2 and the Ministra portal answer HTTP 503 with the message and, when an end time is set, Retry-After. Load balancers answer the same: the switch reaches them with their settings.
    • Торговые посредники не удается выполнить вход: на странице входа в систему отображается сообщение вместо формы, реселлер, уже выполнивший вход, выходит из системы на следующей странице, а API реселлера отвечает на 503 с помощью {"status":"STATUS_FAILURE","error":"<message>"}.
    • Администраторы работайте как обычно, и зрители уже смотрят продолжайте следить: потоки не прерываются.

    Заканчивается на в это время он отключается сам по себе (в зависимости от часового пояса панели); если оставить пустым, он будет включен до тех пор, пока не будет выключен. Сообщение это то, что читают клиенты и торговые посредники; пустое значение означает "Сервис находится на техническом обслуживании". Пожалуйста, повторите попытку позже." Пока он включен, на панели мониторинга отображается баннер с указанием времени окончания.

    Параметр Admin API edit_settings устанавливает те же ключи: maintenance_mode (0/1), maintenance_until ( время Unix, 0 - без конца) и maintenance_message.

    Показатели и проверка работоспособности¶

    ОСНОВНЫЕ ответы на две конечные точки мониторинга на его HTTP-порту (балансировщики нагрузки этого не делают):

    • /healthz needs no credentials and answers only 200 ok or 503 fail: fail when the database does not answer or a check of the dashboard's Service Status card is red (a server down, a failed migration, a full disk, an overdue backup, ...). Point an uptime monitor at it.
    • /metrics отвечает текстовый формат Prometheus на токен Настройки → API → Токен метрики (сгенерируйте его там; пусто, /metrics ответов 404). Отправьте его как Authorization: Bearer <token>; он не используется в URL-адресе, где его хранят браузеры, прокси-серверы и инструменты. Неверный или отсутствующий токен отвечает на 401.
    # prometheus.yml
scrape_configs:
  - job_name: xcvm
    scheme: http
    metrics_path: /metrics
    authorization:
      credentials: <the Metrics Token>
    static_configs:
      - targets: ['main.example.com:80']
    Метрический Этикетки Ценность
    xcvm_up 1
    xcvm_server_online server, name 1 когда включенный сервер ответит на ГЛАВНЫЙ
    xcvm_server_cpu_percent, xcvm_server_memory_percent server, name как в последний раз сообщал сервер
    xcvm_server_disk_free_bytes, xcvm_server_disk_total_bytes server, name диск на панели управления сервера
    xcvm_server_network_bytes_per_second server, name, direction (in/out) как в последний раз сообщал сервер
    xcvm_server_connections server, name подключения к системе просмотра
    xcvm_server_streams server, name, state (running/down) потоки на сервере
    xcvm_lines state (active/expired/disabled) линии
    xcvm_last_run_age_seconds job (root_cron/backup/cache) секунды с момента его последнего запуска
    xcvm_status_check check (servers, clock, schema, crons, fanout, cluster, disk, backups, certs, cache) -1 выкл., 0 ок, 1 предупреждение, 2 сбоя

    При включенном cluster API в нем зарегистрированы средства балансировки нагрузки, как показано на Серверы → Узлы кластера:

    Метрический Этикетки Ценность
    xcvm_cluster_node server, name, state (active/quarantined/…), health (ok/suspect/offline/unknown), mode 1
    xcvm_cluster_node_last_seen_seconds server, name секунды с тех пор, как главный в последний раз связывался с узлом
    xcvm_cluster_node_clock_offset_seconds server, name тактовая частота узла меньше основной
    xcvm_cluster_node_lane_lag_seconds server, name, lane (p0/p1) как долго события узла на этой полосе были отложены; 0, если они не
    xcvm_cluster_node_unreachable_urls server, name ОСНОВНЫЕ адреса, до которых узел не может добраться
    xcvm_cluster_node_streams_local server, name 1, когда узел считывает свои потоки сам по себе, 0, когда нет (только узлы, которые сообщают об этом)
    xcvm_cluster_node_commands_queued server, name команды были поставлены в очередь для узла, и он не был подтвержден
    xcvm_cluster_command_latency_seconds stage (deliver/ack), quantile (0.5/0.99) секунды с момента постановки команды в очередь до ее отправки или подтверждения в последнем окне

    Оба они вычисляются не чаще чем каждые 15 секунд; более быстрый поиск дает один и тот же результат. Показатели для каждого потока не учитываются: при тысячах потоков они затопили бы Prometheus.

    Оповещения¶

    Оповещения (меню профиля, для администраторов с правами настройки) отправляет сообщение, когда что-то идет не так на панели, и еще одно, когда все заканчивается. cron:alerts проверяет каждую минуту на главном экране.

    Каналы¶

    Добавьте один или несколько каналов, затем нажмите Тест на каждом из них: должно прийти тестовое сообщение.

    • Телеграмма: создайте бота с помощью @BotFather и вставьте его Токен бота. Идентификатор чата - это то, куда отправляются оповещения: ваш собственный идентификатор пользователя (сначала напишите боту один раз), идентификатор группы (отрицательный; добавьте бота в группу) или @channelname (сделайте бота администратором канала).

    • Веб-крючок: JSON-файл POST вместо URL-адрес, который вы предоставляете для ваших собственных инструментов (входящий веб-интерфейс приложения для чата, менеджер инцидентов, скрипт). При Секрет подписи каждый запрос содержит X-XCVM-Signature: sha256=<HMAC-SHA256 of the body with the secret>; сравните его, прежде чем доверять тексту. X-XCVM-Event дает название событию: alert здесь, lines.expiring для напоминаний об истечении срока действия.

      {"event": "alert", "state": "fired", "rule": "server_down", "title": "[Panel] A server is down (1)",
 "text": "- LB-2", "items": [{"subject": "2", "label": "LB-2"}], "panel": "Panel", "time": 1800000000}

    state - это fired, resolved или test. - Электронная почта (SMTP): ваш почтовый сервер, его порт и безопасность (SSL/TLS на 465, STARTTLS на 587, нет), учетная запись, отправитель и один или несколько получателей.

    Секреты (токен бота, секрет подписи, SMTP-пароль) после сохранения больше никогда не отображаются; оставьте поле пустым, чтобы сохранить сохраненный пароль.

    Пороговое значение и продолжительность в минутах могут быть изменены для каждого правила, и каждое правило может применяться только к некоторым каналам (не выбран ни один из них: все включенные каналы). Сообщение о том, что тема закрыта, не объявляется в течение 15 минут, поэтому сервер, который закрывается, выдает одно сообщение, а не по одному в минуту. Темы одного правила, которые срабатывают в одну и ту же минуту, выводятся в виде одного сообщения, в котором указывается не более 20 имен. Отключенное правило не отправляет сообщения "разрешено", о котором оно сообщало.

    Последние сообщения перечисляет, что было отправлено и как ответил каждый канал.

    Напоминания об истечении срока действия¶

    Настройки → Общие → Напоминания об истечении срока действия напоминает об этом подписчикам и их торговому посреднику перед окончанием линии. cron:reminders запускается один раз в день на ГЛАВНОЙ странице (09:00).

    • Дней до истечения срока годности: например, 7,3,1. Подключенная строка, которая не является пробной, получает одно напоминание в наименьший из дней, в течение которого у нее осталось время: строка, которая заканчивается через два дня, получает напоминание на 3 дня, а на следующий день - на 1 день. Обновление линии (новый срок годности) начинается сначала.
    • Отправьте электронное письмо владельцу: каждый реселлер или администратор, у которого в профиле указан адрес электронной почты, получает список своих сообщений, срок действия которых скоро истечет. Рассылка осуществляется по первому включенному каналу электронной почты Оповещения.
    • Сообщение на устройствах MAG: магнитное устройство линии отображает на экране значение Сообщение подписчика.
    • Телеграмма подписчику: бот выбранного вами Telegram-канала отправит подписчику сообщение Сообщение подписчика. Смотреть ниже.

    • Веб-интерфейс для выставления счетов: каждый включенный канал webhook получает одну строку POST со списком строк:

      {"event": "lines.expiring", "lines": [{"id": 12, "username": "alice", "owner_id": 5, "exp_date": 1800172800, "days": 3}],
 "panel": "Panel", "time": 1800000000}

    Сообщение подписчика может использовать {date} (дата окончания) и {line} (имя пользователя строки).

    Телеграмма¶

    Бот может написать только тому, кто написал ему первым, поэтому разговор начинает подписчик:

    1. Выберите канал Telegram, на который бот отправляет напоминания. Это может быть собственный канал оповещений. Канал, используемый только для напоминаний, все равно должен быть включен, поэтому предоставьте правилам оповещений их каналы, чтобы они не включали оповещения.
    2. Введите логин подписчика в Telegram (@name) в поле Телеграмма на его линии, устройстве MAG или устройстве Enigma2. Реселлеры также могут заполнить это поле.
    3. Подписчик запускает бота в Telegram и отправляет /start. /stop завершает напоминания; /start снова возобновляет их.

    Бот отвечает на запрос /start тем же способом, что и тот, кто его отправляет, поэтому он никому не сообщает, какие имена пользователей известны панели. Читаются только личные чаты: /start в группе игнорируется. cron:alerts читает сообщения бота каждую минуту, поэтому не подключайте того же бота к другой программе, которая читает его обновления.

    Резервные копии за пределами сайта¶

    Страница Резервные копии копирует каждую резервную копию, созданную cron:backups, и пакет восстановления за каждый день в одну или несколько целевых программ Копии за пределами сайта, как только они создаются:

    • Совместимость с S3 хранилища: AWS S3, Backblaze B2, Wasabi, MinIO и другие. Укажите значения Конечная точка (пустое: AWS), Регион, Ведро, необязательное значение Папка и ключ доступа, который может использоваться для записи, перечисления и удаления. Отметьте URL-адреса в стиле Path для MinIO и других серверов, которые не используют корзину в качестве имени хоста.
    • SFTP: a server, a user with a password or an RSA private key in PEM form, and an absolute Folder. The panel keeps the server's host key fingerprint the first time it connects and refuses any other key after; clear the fingerprint to accept a server whose key really changed.

    Держи - это количество самых новых резервных копий и, кроме них, самых новых пакетов, которые хранит целевой объект (All: ни одна из них не удалена). Нажмите Тест после сохранения: программа записывает, отображает и удаляет небольшой файл. Неудачная загрузка записывается рядом с резервной копией, а строка Резервные копии на панели мониторинга становится желтой.

    Пакет для восстановления¶

    Резервная копия базы данных не содержит того, что требуется новой основной системе, кроме: config/config.ini (учетных данных базы данных), конфигурации модулей и, при настройке cluster API, ключей кластера (см. Ключи кластера). Задайте Ключевая фраза из 20 символов или более в поле Пакет для восстановления и cron:backups записывайте по одному набору в день, backups/recovery_<date>.bundle зашифровывайте с его помощью (Argon2id и XSalsa20-Poly1305), сохраняйте последние 7 и копируйте их в целевые файлы.

    Ключевая фраза хранится в config/backup_bundle.pass, вне базы данных, поэтому ни в одной резервной копии она не хранится. Сохраните его копию на этом компьютере: без нее пакеты не могут быть открыты. Чтобы открыть один из них на новом главном:

    sudo /home/xc_vm/console.php backup:open-bundle recovery_2026-10-07_04-00-00.bundle /root/restore < passphrase.txt

    Кодовая фраза считывается из стандартного ввода, поэтому ее нет в списке процессов или истории командной строки. Каталог не должен существовать; он создается с использованием файлов пакета. Экспорт ключа кластера в него импортируется с помощью cluster:import-keys и той же кодовой фразы.

    Тест на восстановление¶

    Каждое воскресенье в 05:00 cron:backup_verify восстанавливает последнюю резервную копию в базе данных scratch xc_vm_migrate, проверяет, восстановлены ли ее таблицы и настройки, и снова очищает базу данных scratch. Беги сейчас же сразу же запускает ее. Результат отображается на странице резервных копий, а при неудачном тестировании строка Резервные копии панели управления становится желтой. Пока xc_vm_migrate содержит таблицы (выполняется миграция), тест пропускается и они остаются в покое.
