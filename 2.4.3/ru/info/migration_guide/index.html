    XC_VM Руководство по миграции¶

    Безопасная миграция с совместимых IPTV-систем с помощью встроенных инструментов миграции XC_VM.

    Важное уведомление о переносе¶

    Read this before starting the migration.

    XC_VM миграционные переводы только данные. All configuration is intentionally excluded from migration.

    Это включает в себя (но не ограничивается этим):

    • Ключи API (например, ТМДб)
    • Учетные данные внешней службы
    • Настройки, зависящие от конкретной среды
    • Конфигурация панели и системы
    • Время выполнения и состояние потока

    Эти значения необходимо перенастроить вручную после миграции.

    Это дизайнерское решение, а не ограничение или ошибка. Пропуск реконфигурации приведет к прерывать выборку метаданных, обновлять заголовки потоков и связанные с ними функции.

    Прежде чем Вы начнете¶

    💡 Рекомендация: Выполните перенос на новая установка XC_VM.

    ⚠️ Важный: Системные настройки и настройки панели равны НЕ перенесен. Передаются только данные базы данных, поддерживаемые процессом миграции.

    Если вы решите перейти на существующая установка, имейте в виду:

    • XC_VM будет удалить все таблицы в основной базе данных, которая соответствует данным из базы данных миграции.
    • Резервное копирование является обязательным. Автоматический откат не предусмотрен.

    Этапы миграции¶

    1. Загрузить резервную копию¶

    Загрузите существующую резервную копию базы данных на сервер XC_VM с помощью SFTP-протокол.

    Примерное местоположение:

    /tmp/backup.sql

    2. Восстановить резервную копию в базе данных миграции¶

    Очистите базу данных миграции и восстановите резервную копию:

    sudo /home/xc_vm/console.php tools migration "/tmp/backup.sql"

    Прежде чем продолжить, убедитесь, что восстановление завершено без ошибок.

    3. Начать миграцию¶

    Как только резервная копия будет восстановлена, запустите миграцию, используя один из следующих способов.

    Вариант 1 — Командная строка (рекомендуется)¶

    /home/xc_vm/console.php migrate

    Вариант 2 — Веб-установщик¶

    • Вернитесь к веб-установщик (ссылка, показанная при настройке панели).
    • Выберите Миграция
    • Следуйте инструкциям на экране

    Вы будете видеть обновления о ходе выполнения в режиме реального времени. После завершения работы система будет доступна.

    Восстановление Доступа После Миграции¶

    Если войти в систему не удается из-за отсутствия учетных данных или кода доступа, воспользуйтесь средствами восстановления.

    Создайте аварийный код доступа¶

    sudo /home/xc_vm/console.php tools access

    Создайте учетную запись администратора¶

    sudo /home/xc_vm/console.php tools user

    ❗️ После восстановления доступа введите немедленно измените код доступа и учетные данные администратора.

    Подготовка балансировщика нагрузки¶

    Балансировщики нагрузки имеют значение не перенесен.

    • При необходимости переустановите операционную систему
    • Перенастройка сети и маршрутизации
    • Повторно подключите их к основному серверу

    Постмиграционный период (обязательно)¶

    После миграции система будет находиться в состоянии не готов к производству до тех пор, пока эти шаги не будут выполнены.

    Пропуск их приведет к результату ожидаемое, но нарушенное поведение.

    1. Повторная инициализация состояния среды выполнения¶

    • Запускайте все потоки вручную
    • Убедитесь, что потоки доступны и стабильны

    Состояние выполнения потока во время миграции равно никогда не сохранявшийся.

    2. Перенастроить системные параметры¶

    Просмотрите и восстановите все настройки, зависящие от конкретной среды:

    • Пути к файлам
    • Ограничения и квоты
    • Настройки сети и обратного прокси-сервера
    • Настройка производительности

    Сделайте нет вывод, что значения по умолчанию соответствуют вашим предыдущим настройкам. Значения по умолчанию применяются намеренно.

    3. Восстановление ключей API и поставщиков¶

    Ключи API Никогда Не Переносятся¶

    Следующее необходимо перенастроить вручную:

    • TMDb API key

    Это ожидаемое поведение.

    Если выборка метаданных не работает после миграции, убедитесь, что ключ API был повторно добавлен и поставщик включен. This does not indicate a migration bug.

    Общие проблемы после миграции¶

    Метаданные Не извлекаются (TMDb)¶

    Cause: Ключ API TMDb и конфигурация поставщика не были восстановлены.

    Resolution: Повторно добавьте ключ API TMDb и включите провайдера в настройках главного сервера.

    Резюме¶

    • Миграционные переводы только основные данные приложения
    • Конфигурация равна исключено по замыслу
    • Ключи API и настройки, зависящие от среды необходимо восстановить вручную
    • Недостающая функциональность после миграции равна ожидается до завершения реконфигурации
