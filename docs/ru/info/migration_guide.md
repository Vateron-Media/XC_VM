# XC_VM Руководство по миграции

Безопасная миграция с совместимых IPTV-систем с помощью встроенных инструментов миграции XC_VM.

---

## Важное уведомление о переносе

> **Прочтите это перед началом миграции.**

XC_VM миграция переносит только **данные**.
**Вся конфигурация намеренно исключена из процесса миграции.**

Это включает в себя (но не ограничивается этим):

- Ключи API (например, **TMDb**)
- Учетные данные внешней службы
- Настройки, зависящие от конкретной среды
- Конфигурация панели и системы
- Время выполнения и состояние потока

Эти значения ** должны быть перенастроены вручную после миграции**.

Это ** дизайнерское решение**, а не ограничение или ошибка.
Пропуск переконфигурации приведет к ** прерыванию выборки метаданных, обновлению заголовков потоков и связанных с ними функций **.

---

## Прежде чем Вы начнете

> 💡 **Рекомендация:**
> Выполните миграцию на **новой установке XC_VM**.
>
> ⚠️ **Важно:**
> Системные настройки и настройки панели ** НЕ перенесены**.
> Передаются только данные базы данных, поддерживаемые процессом миграции.

Если вы решите перейти на **существующую установку**, имейте в виду:

- XC_VM приведет к удалению всех таблиц** в основной базе данных, которые соответствуют данным из базы данных миграции.
- **Резервное копирование является обязательным.** Автоматический откат не предусмотрен.

---

## Этапы миграции

### 1. Загрузить резервную копию

Загрузите существующую резервную копию базы данных на сервер XC_VM, используя **SFTP**.

Примерное местоположение:

```text
/tmp/backup.sql
```

---

### 2. Восстановить резервную копию в базе данных миграции

Очистите базу данных миграции и восстановите резервную копию:

```bash
sudo /home/xc_vm/console.php tools migration "/tmp/backup.sql"
```

Прежде чем продолжить, убедитесь, что восстановление завершилось ** без ошибок**.

---

### 3. Начать миграцию

Как только резервная копия будет восстановлена, запустите миграцию, используя один из следующих способов.

#### Вариант 1 — Командная строка (рекомендуется)

```bash
/home/xc_vm/console.php migrate
```

#### Вариант 2 — Веб-установщик

- Вернитесь к веб-установщику ** (ссылка показана во время настройки панели).
- Выберите **Перенос**
- Следуйте инструкциям на экране

Вы будете видеть обновления о ходе выполнения в режиме реального времени.
После завершения работы система будет доступна.

---

## Восстановление Доступа После Миграции

Если войти в систему не удается из-за отсутствия учетных данных или кода доступа, воспользуйтесь средствами восстановления.

### Создайте аварийный код доступа

```bash
sudo /home/xc_vm/console.php tools access
```

### Создайте учетную запись администратора

```bash
sudo /home/xc_vm/console.php tools user
```

> ❗️ После восстановления доступа ** немедленно измените ** код доступа и учетные данные администратора.

---

## Подготовка балансировщика нагрузки

Подсистемы балансировки нагрузки **не перенесены**.

- При необходимости переустановите операционную систему
- Перенастройка сети и маршрутизации
- Повторно подключите их к основному серверу

---

## Постмиграционный период (обязательно)

После миграции система ** не готова к работе** до тех пор, пока не будут выполнены эти шаги.

Пропуск их приведет к ** ожидаемому, но нарушенному поведению **.

---

### 1. Повторная инициализация состояния среды выполнения

- Запускайте все потоки вручную
- Убедитесь, что потоки доступны и стабильны

> Состояние выполнения потока ** никогда не сохраняется ** во время миграции.

---

### 2. Перенастроить системные параметры

Просмотрите и восстановите все настройки, зависящие от конкретной среды:

- Пути к файлам
- Ограничения и квоты
- Настройки сети и обратного прокси-сервера
- Настройка производительности

> Не предполагайте, что значения по умолчанию соответствуют вашим предыдущим настройкам.
> Значения по умолчанию применяются намеренно.

---

### 3. Восстановление ключей API и поставщиков

#### Ключи API Никогда Не Переносятся

Следующие параметры ** необходимо перенастроить вручную**:

- **Ключ API TMDb**

Это ** ожидаемое поведение**.

> Если выборка метаданных не работает после миграции,
> убедитесь, что ключ API был повторно добавлен и поставщик включен.
> Это не указывает на ошибку переноса.

---

## Общие проблемы после миграции

### Метаданные Не извлекаются (TMDb)

**Причина:**
Ключ API TMDb и конфигурация поставщика не были восстановлены.

**Разрешение:**
Повторно добавьте ключ API TMDb и включите провайдера в настройках главного сервера.

---

## Резюме

- Миграционный перенос ** только основных данных приложения**
- Конфигурация ** исключена по замыслу**
- Ключи API и настройки, зависящие от среды **, должны быть восстановлены вручную**
- Отсутствие функциональности после миграции ** ожидается до завершения реконфигурации**
