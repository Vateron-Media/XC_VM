# <a id="combining-epg-sources"></a>Объединение EPG источников

Перед использованием этой функции выполните миграцию базы данных `103_add_epg_merge`, `104_add_stream_epg_bindings` и `105_add_epg_merge_lookup` с помощью обычного средства обновления XC_VM.

## <a id="search-and-select-multiple-epg-entries"></a>Выполните поиск и выберите несколько записей EPG

Откройте **Потоки → Редактировать канал → EPG → Поиск EPG**. Выполните поиск по названию канала, при необходимости выберите источник и нажмите **+** рядом с каждым желаемым результатом. В выбранном списке отображается источник и точный идентификатор канала. Используйте стрелки, чтобы установить приоритет или удалить отдельные записи. Поддерживается несколько разных идентификаторов из одного и того же источника.

Сохраните канал. Автоматически начнется импорт его руководства. Приоритет имеет первая выбранная запись; если в ней нет допустимых программ, их добавляет следующая. Более поздние записи также заполняют все незакрытые временные интервалы. Существующие правила неперекрывания и последних допустимых данных по-прежнему применяются. Выбранные вами варианты являются фиксированными идентификаторами, а не нечеткими совпадениями, поэтому они остаются именно теми записями, которые вы выбрали.

При переносе `104_add_stream_epg_bindings` сохраняются упорядоченные записи для каждого канала. Это метаданные панели MAIN; существующие `epg_id` и `channel_id` продолжают содержать материализованное руководство для игроков и узлов. Используются настроенные пользователем источники XMLTV. Импорт EPG провайдера является отдельным действием существующей панели и не является частью рабочего процесса выбора канала.

## <a id="manual-source-level-merge"></a>Ручное слияние на уровне исходного кода

Приведенное ниже слияние на уровне исходного кода остается доступным для явного сопоставления каналов.

1. Добавьте свои исходники XMLTV в поле **EPG** и перезагрузите их один раз.
2. Добавьте новый источник EPG и включите **Объединение нескольких источников EPG**.
3. Выберите два или более обычных источника и распределите их по приоритетам. Выигрывают меньшие числа; равные числа используют порядок идентификаторов источников.
4. Идентичные идентификаторы каналов XMLTV автоматически объединяются. Для разных идентификаторов добавьте сопоставление каналов: целевой идентификатор, входной источник и идентификатор канала этого источника. Например, целевой `news.de`, резервный источник, входной `NewsGermany`.
5. Сохраните и перезагрузите объединенный источник. Это также обновит его входные данные. Его каналы теперь отображаются в селекторе обычного потока EPG.
6. Назначьте потоки каналам из объединенного источника и перезагрузите их снова. Импортер выбирает программы для назначенных каналов, даже если их источники ввода не назначены потокам напрямую.

Обычный EPG cron поддерживает объединенное руководство. При повторной загрузке входных данных объединенные руководства также перестраиваются из последних сохраненных входных данных. Объединенный исходный код работает с существующими экспортными данными XMLTV и кэшами для каждого потокового проигрывателя.

Выигрывают программы с более высоким приоритетом. Резервные копии заполняют только полные, непересекающиеся интервалы; программы никогда не разбиваются на фрагменты. Резервное копирование, начатое до завершения существующей программы, пропускается, поэтому могут оставаться небольшие пробелы. Ни одна система не сможет предоставить недостающие списки, если они отсутствуют во всех входных данных. На странице редактирования отображается трансляция на следующие 24 часа и последнее окончание программы для каждого назначенного канала.

При неправильной загрузке, некорректном формате XML и неудачной замене базы данных сохраняются последние успешно выполненные данные. Старое объединенное руководство используется только в том случае, если при вводе данных произошел сбой, а порядок исходных данных, сопоставления и выбранные языки по-прежнему совпадают. Успешная перезагрузка не приводит к повторному внедрению программ, удаленных при вводе данных. Срок действия его записей по-прежнему истекает в соответствии с их фактическим временем выполнения программы. В статусе отображаются идентификаторы ошибочного ввода, обнаруженные во время последней перезагрузки.

Идентификаторы каналов отображаются явно; похожие названия каналов не сопоставляются автоматически. Объединенные идентификаторы каналов стабильны и отличаются от входных идентификаторов, что предотвращает конфликты в экспортируемом XMLTV. Изменение целевого идентификатора требует переназначения затронутых потоков. Удаление источника, используемого при слиянии, отклоняется. Переключение назначенного источника между обычным и объединенным режимами запрещено; вместо этого создайте отдельный источник.

Объединяемые источники не могут содержать другие объединяемые каналы или руководство по зарезервированным созданным каналам. Поддерживается до 20 входных данных и 1000 сопоставлений вручную. Перед объединением применяются смещения часовых поясов источника; слияние не имеет дополнительного смещения. Существующий единый предпочтительный язык передачи для каждого входного канала остается в силе.

Сохранение конфигурации, удаление введенных данных, создание внутренней группы и публикация из выбранного источника приводят к блокировке базы данных. Редактирование, выполненное во время загрузки исходного кода, приводит к удалению более старого ответа. Создание потока и его окончательный идентификатор канала выбора фиксируются атомарно. Запрошенная перезагрузка ожидает активного импортера, а не отбрасывается. Неудачные запуски процессов регистрируются в журнале; запланированное обновление EPG остается доступным.

Неиспользуемые внутренние направляющие для выбора удаляются при проверке удаления источника. Они исключаются из устаревшего поиска и автоматического назначения. Для каждого выбранного объекта сохраняется самая длинная настроенная история его входных данных; ноль означает, что импортер не накладывает дополнительное ограничение на историю. Срок действия истории исходных данных по-прежнему истекает после неудачной загрузки. Прерванное слияние сохраняет свои предыдущие данные и не останавливает другие руководства, генерацию XMLTV или обновление потокового кэша.

Миграция 105 добавляет `(epg_id, channel_id, end, start)` для поиска по каждому каналу. Типичная таблица из 10 000 строк использует этот индекс и проверяет только запрошенный диапазон источника/канала; для `ORDER BY start` все еще может потребоваться сортировка файлов после поиска по индексированному диапазону.
